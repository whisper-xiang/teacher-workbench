# 教学工作台 · 产品改进 PRD

- **视角**：大学教育学讲师（日常用户，而非产品经理）
- **日期**：2026-08-13
- **状态**：P0 / M1、P1 / M2、P2-2 已落地（2026-08-13）；P2-1 待排期
- **范围**：在保持「本地、轻量、懂师范教师」优势的前提下，从「个人节奏台」升级为名副其实的「教学工作台」

---

## 1. 背景与定位

**现状定位**：本地离线、单人使用的高校教师个人工作台（`localStorage` + JSON 导入导出，无后端 / 账号）。人群画像精准——师范院校教育学院教师，覆盖值班、巡视、实习巡视、教研会等专属场景，并按教育学 / 小学教育 / 学前教育三专业分流。

**核心矛盾**：产品名叫「教学工作台」，但当前能力集中在**个人日程与提醒**；教育学教师最看重的**课程内容管理、学生过程性评价、备课资源**要么只有数据模型没有页面，要么只是壳。

**衡量成功的关键问题**：老师每天第一件事会不会打开它？它能否替代「课表截图 + 备忘录 + Excel 成绩表 + 网盘课件」这套零散工具组合？

---

## 2. 目标用户与高频场景

| 用户 | 一周高频动作 |
|------|------------|
| 教育学院讲师 / 副教授（如种子中的李明华） | 给多专业班级上课、坐班值班、巡考、下附小做实习巡视、开课程组教研会、批改作业、录期中成绩、准备实习材料 |

三个专业方向：教育学（`edu`）、小学教育（`pri`）、学前教育（`pre`）。

| 维度 | 评价 | 说明 |
|------|------|------|

## 4. 优先级定义

- **P0（必做，本产品立命之本）**：不补齐就配不上「教学工作台」之名。
- **P1（强烈建议）**：显著提升日常黏性与专业性。
- **P2（增值）**：锦上添花，可延后。

## 5. 改进清单

### P0-1　落地「学生与过程性评价」模块

- **问题**：教育学专业最核心的主张是「重过程、重形成性评价」，但这恰恰是产品的空白。
- **依据**：`src/data/types.ts` 已完整定义 `StudentRecord`（考勤、作业、`processScore`、状态）、`Assignment`、`GradeItem`（平时 / 期中 / 期末 / 总评）与 `letterGrade()`，但 `src/App.tsx` 路由里没有学生 / 成绩 / 作业页面。
- **需求**：
  1. 新增路由 `students`（学生与评价），进入方式：课程卡片 → 查看学生。
  2. 学生列表：按课程 / 班级 / 专业筛选，展示考勤、作业提交、过程分、状态标签。
  3. 过程性评价录入：可编辑 `processScore` 与 `notes`，支持快速批量标记（如「本次到勤 / 迟交」）。
  4. 成绩汇总：基于 `GradeItem` 计算总评并用 `letterGrade()` 显示 A–F。
  5. 花名册导入：支持粘贴 / CSV 导入学生名单（暂本地）。
- **验收标准**：能为任一课程新增学生 → 录入平时 / 期中 / 期末 → 自动算总评与等级 → 数据随 JSON 导出。
- **涉及**：新建 `src/pages/StudentsPage.tsx`（成绩可合并进同一页）、`src/App.tsx` 路由与导航、`useWorkbenchStore` 的 `students` / `assignments` / `grades` patch。
- **实现**：2026-08-13。路由 `#/students/:courseId`；课程卡片进入；作业批改回写 `homework` 并同步日历截止。

### P0-2　课程从「课表格子」升级为「课程档案（syllabus 化）」

- **问题**：目前「课程」只是周课表里的一个时间格，无法承载真正的教学内容。
- **依据**：`CoursesPage` 注释写「一门课 · 一个时段」，只使用 `sessions[0]`；`code` 固定 `EDU000`、`topic` 默认「待补充教学主题」、`credits` 默认 2。
- **需求**：
  1. **支持多时段**（`sessions` 数组真正生效）——解决《教育研究方法》一周两次 + 晚上补课（种子 `d5`）无法表达的问题。
  2. 课程详情页：编辑课程简介、学分、课程编号、**16 周教学主题（周计划 syllabus）**。
  3. 周主题与 Dashboard「本周：{topic}」打通，按 `currentWeek` 自动显示当周主题。
- **验收标准**：一门课可添加 ≥2 个上课时段并全部出现在周课表；可逐周填写教学主题；概览页显示当周主题。
- **涉及**：`src/pages/CoursesPage.tsx`、`src/data/sync.ts`（`syncCourseEvents` 需支持多 session）、`src/data/types.ts`（可加 `weeklyTopics?: string[]`）。
- **实现**：2026-08-13。`weeklyTopics`、多时段编辑、晚上节次、`教育研究方法` 种子为周四下午 + 周二晚补课。

### P0-3　修复「今天」硬编码，回归真实时间

- **问题**：作为日更工具，时间与现实脱节会直接损害信任。
- **依据**：`src/pages/Dashboard.tsx` 将「今天」兜底硬编码为 `'2025-05-13'`（仅当真实日期无事件时）。
- **需求**：默认以真实系统日期为「今天」；将演示数据日期改为相对当前日期动态生成（参考 `seed.ts` 中 reminders 已用 `new Date()` 的做法），或提供「演示模式」开关（`meta.demoBanner` 已存在，可复用）。
- **验收标准**：非演示模式下，概览「今日安排 / 值班」始终基于真实当天。
- **涉及**：`src/pages/Dashboard.tsx`、`src/data/seed.ts`、`src/pages/SettingsPage.tsx`（演示开关）。
- **实现**：2026-08-13。概览使用 `todayIso()`；种子相对本周一；旧演示周 `2025-05-12` 在演示模式下自动对齐；设置页可手动「对齐到本周」。

### P1-1　AI 助手从「原型壳」接通真实写入

- **问题**：最吸引老师的卖点（说一句就建课 / 提醒 / 传资源）目前点不动。
- **依据**：`src/components/AiAssistantPanel.tsx` 的 `mockReply` 所有回复都带「（原型）…尚未连接真实写入逻辑」。
- **需求**（分两档，按落地成本选其一）：
  - **轻量档（推荐先做）**：接通**提醒**这一条——复用已存在的 `reminder-nlp` 解析能力，让 AI 面板真的能把自然语言写入 `reminders`（无需外部大模型）。
  - **完整档**：接入可配置的 LLM（在设置里填 API Key），解析后弹出结构化草稿卡片 → 用户确认 → 写入课程 / 资源 / 任务 / 提醒。
- **验收标准**：至少「提醒」类指令能真实落库并触发系统通知；其余类型给出明确「确认后写入」的草稿交互，去掉「（原型）」字样。
- **涉及**：`src/components/AiAssistantPanel.tsx`、`src/lib/reminder-nlp.ts`、`useWorkbenchStore`、`SettingsPage`（LLM 配置，若做完整档）。
- **实现**：2026-08-13。本地解析 + 确认卡片写入提醒 / 课程时段 / 资源索引 / 看板任务；未接外部 LLM。

### P1-2　资源库支持真正的文件托管与备课绑定

- **问题**：备课是高频动作，但资源库只是「我有这个」的索引卡。
- **依据**：`TeachingResource` 只有 `size` / `format` 文本 + 标签，无文件上传 / 预览；`RESOURCE_TYPES` 为课件 / 教案 / 试题 / 视频 / 文献。
- **需求**：
  1. 支持本地文件拖入（用 IndexedDB 存二进制，避免撑爆 localStorage），可下载 / 预览。
  2. 资源与课程强绑定（已有 `course` 字段），课程详情页可直接看「本课资源」。
  3. `usedCount` / `lastUsed` 打通「标记已用」，帮助老师复用往期课件。
- **验收标准**：上传一份 PPT → 绑定到某课程 → 在该课程详情下可见并可打开 → 导出备份包含引用。
- **涉及**：`src/pages/ResourcesPage.tsx`、`CoursesPage` 详情、存储层（新增 IndexedDB 封装）。
- **实现**：2026-08-13。`src/lib/resource-files.ts` 用 IndexedDB 存文件；课程卡展示本课资源；打开文件计入 `usedCount`。JSON 备份含 `fileId` 引用。

### P1-3　强化「截止事项」的闭环，而非只提醒

- **问题**：deadline 只提醒老师，不帮老师推进。
- **依据**：种子含「期中成绩录入截止到教务系统」「实习巡视材料提交」，但产品无法关联到具体动作。
- **需求**：deadline 事件可关联到目标（如「成绩录入」→ 跳转成绩页；「实习材料」→ 跳转资源库对应打包项），并支持一键「标记已完成」回写。
- **验收标准**：点击一个 deadline 能跳到对应待办 / 页面，完成后该 deadline 状态更新。
- **涉及**：`src/pages/CalendarPage.tsx`、`src/data/types.ts`（`CalendarEvent` 加可选 `linkTo`）、跨页导航。
- **实现**：2026-08-13。`linkTo` + `done`；概览/日历可跳到学生、资源或课程；作业截止同步时保留完成状态。

### P2-1　教研协作的「半自动」补偿（不引入后端）

- **问题**：教育学院大量工作是协作性的（课程组共享教案、成绩上报），单机模式无法直接对接。
- **需求**：在不做后端的前提下，提供**结构化导出**——按课程导出成绩单 CSV、按实习导出巡视材料清单、生成可发给同事的教案分享包（JSON + 文件）。
- **验收标准**：能一键导出符合常见教务模板的成绩 CSV。
- **涉及**：`SettingsPage` / 各页面的导出增强。

### P2-2　工具箱与资讯的教育学垂直化

- **依据**：`ToolsPage` 已做得较完整（分类、常用置顶、搜索）；`NewsPage` 走 RSS。
- **需求**：预置面向教育学的默认工具与 RSS 源（如知网 / 教育部 / 学前教育研究相关），降低老师从零配置的成本。
- **验收标准**：初次打开即有一批高相关的默认工具与资讯源。
- **涉及**：`src/data/seed.ts`、`src/lib/rss.ts`。
- **实现**：2026-08-13。预置教育部 / 知网 / 学前教育研究 / 智慧教育平台等工具；RSS 改为中新网教育、科学网人才高教与教学心得；资讯页列出教育部等官网入口。已有本地数据按工具 `id` 补齐一次，不覆盖用户自建项。

## 7. 非目标（本轮不做）

- 不做多用户账号体系 / 云端同步（保留「本地、隐私」这一核心优势）。
- 不做直连教务系统的在线上报（改用结构化导出作为过渡）。
- 不做移动端原生 App（现有响应式布局已够用）。

## 8. 实现约定

后续按本 PRD 排期或实现时：

- 保持本地优先：数据仍走 `teacher-workbench-data-v1`（localStorage），备份走设置页 JSON 导入导出。
- 优先复用已有类型与同步层（`src/data/types.ts`、`src/data/sync.ts`），避免平行造一套模型。
- 课程 / 作业变更继续走现有闭环：排课 → 日历课程事件；作业截止 → 日历 deadline。
- 完成某一条目后，在该条目下标注实现日期与主要文件，避免文档与代码脱节。
